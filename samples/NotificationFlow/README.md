# Полный сценарий подготовки уведомления

[English](README.en.md)

Пример сохраняет определения параметров и текст шаблона в SQL Server, находит шаблон по коду, передаёт идентификатор клиента в TemplateEngine и выводит готовое сообщение. Данные читает настоящий SQL-запрос, сформированный SqlServerQueryGenerator. Заглушек поставщика данных нет.

## Запуск

Нужны .NET 10 SDK и SQL Server. В Windows по умолчанию используется установленный SQL Server LocalDB, экземпляр MSSQLLocalDB, база tempdb.

Из корня репозитория:

```powershell
dotnet run --project samples/NotificationFlow
```

Для другой учебной базы задайте строку подключения в переменной окружения DEVELKIT_SAMPLE_SQL. Пример требует прав на создание схемы и таблиц. Используйте отдельную тестовую базу. Не записывайте пароль в исходники.

При каждом запуске создаётся уникальная схема notification_demo_<guid>. Создание объектов и все операции идут в одной транзакции, которая откатывается в finally. Шаблоны и клиенты сохраняются в SQL на время демонстрации. После завершения таблиц и данных примера не остаётся.

## Что происходит

1. NotificationCatalog создаёт таблицы parameters, templates, fieldMetadata и person.
2. Администратор добавляет {{Клиент:Имя}} и {{Встреча:Дата}} с техническими определениями.
3. Автор сохраняет текст под кодом meeting-reminder.
4. NotificationService находит текст по коду и загружает каталог параметров.
5. TemplateEngine раскрывает параметры, разбирает текст и строит план для person с переданным id.
6. PreparingTemplateDataProvider читает метаданные и добавляет поле смещения времени. SqlServerTemplateDataProvider вызывает SqlServerQueryGenerator.Generate, создаёт параметризованную команду, выполняет её и читает поля результата.
7. Декоратор приводит типы и переводит UTC во время клиента. Движок сопоставляет колонки с узлами, форматтер вычисляет условия и собирает сообщение.

```text
Здравствуйте, Анна! Ждём вас 15.09.2026 14:30.
Здравствуйте, Борис! Ждём вас 16.09.2026 10:00.
```

Program.cs содержит проверки двух клиентов с разными смещениями от UTC, обеих веток if после приведения SQL bigint к Int32, буквального вывода SQL-подобной строки, отсутствующего шаблона и отсутствующего клиента. При неверном результате запуск завершится ошибкой.

## Границы примера

NotificationCatalog и NotificationService принадлежат приложению. Библиотека не диктует способ хранения и выбора шаблонов. Для краткости дата единственной встречи находится в person. Переходы между сущностями отдельно показаны в samples/Meetings.

SqlServerTemplateDataProvider использует уже открытое соединение и транзакцию вызывающего кода. Это последовательный демонстрационный сценарий, а не общий провайдер для одновременных запросов. В рабочем приложении отдельно определяют управление соединениями, транзакциями, правами, версиями шаблонов и правилами выбора получателя.

Пример заканчивается подготовкой текста. SMS-тарификация, транслитерация, HTML-кодирование и доставка здесь не реализованы.
Правила подготовки значений: [документация](../../docs/value-preparation.md).
